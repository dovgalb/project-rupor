# 2.1 Комнаты и каналы — документы дизайна

## Бизнес-контекст

Rupor — коммуникационная платформа в формате Discord. После того как в фазе 1 закрыта авторизация, пользователю нужно объединяться в группы (комнаты) и общаться внутри них через каналы. До тех пор, пока нет комнат и каналов, продукт нечем пользоваться даже в внутренней альфа-группе.

Эта фича закрывает фазу 2 общего плана MVP (`/.claude/plans/general_plan.md:127-138`) и даёт минимальный набор примитивов:
- комнаты с владельцем и иерархией ролей (owner / admin / member);
- инвайт-коды для расширения круга участников без публичного реестра;
- каналы внутри комнаты двух типов (`text`, `voice`) — последний пока без сигнализации, она появится в фазе 4.

Сообщения и WebSocket остаются в фазе 3; текущая фича готовит для них транспорт-носитель (каналы) и контекст доступа (членство).

## Критерии приёмки

1. Авторизованный пользователь может **создать комнату**, при этом автоматически становится её **owner**.
2. Авторизованный пользователь видит **список своих комнат** (где он owner, admin или member) и может получить **детальный объект** конкретной комнаты, в которой состоит.
3. Owner может **удалить комнату**; удаление каскадно сносит участников, инвайты и каналы.
4. Owner или admin могут **сгенерировать инвайт-код**: 8 символов, base32 (Crockford alphabet, без `I`/`L`/`O`/`U`). Перевыпуск автоматически отзывает предыдущий код. На комнату — не более одного активного кода в каждый момент времени.
5. Owner или admin могут **отозвать активный код** (опция в виде того же эндпоинта генерации — старый отзывается, новый выдаётся).
6. Любой авторизованный пользователь может **вступить в комнату** по активному коду — становится `member`. Повторное вступление — 409.
7. Любой member может **получить список участников** комнаты с их ролями.
8. Owner или admin могут **создать канал** внутри своей комнаты с типом `text` либо `voice`.
9. Любой member может **получить список каналов** комнаты.
10. Owner или admin могут **удалить канал**.
11. Все эндпоинты защищены JWT (`RequireAuth` middleware из фазы 1.4) и используют унифицированный JSON-envelope ошибок `{"error":{"code":"...","message":"..."}}`.
12. Архитектурные правила (направление импортов между слоями, изоляция `pkg/httpx`) для новых доменов покрыты в `arch_test.go`.
13. Все доменные инварианты, маппинг репозитория и базовые HTTP-сценарии покрыты тестами; есть набор `manual_qa/2_1_rooms_and_channels/*.http` для ручной проверки.

## Out of scope

- Сообщения (фаза 3).
- WebSocket-уведомления `member.joined` / `channel.created` (фаза 3 поверх hub-а).
- WebRTC-сигнализация для voice-каналов (фаза 4).
- Списки публичных комнат / discovery (не нужен для альфы).
- Гранулярные права на канал (private channels, role-overrides) — отложены.
- Soft-delete и история — пока hard-delete c CASCADE.
- Транзитные доменные события (доменный outbox) — отложены, при необходимости введём позже.
